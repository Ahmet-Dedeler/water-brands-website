# AGENTS.md

Water Quality Rank ([waterqualityrank.org](https://waterqualityrank.org)): a static Next.js leaderboard of bottled
waters, home water filters, ingredients and US tap water, scored from lab data scraped from Oasis. README.md covers
setup, the data pipeline, the design/emoji rules and where SEO pages live. Read it before changing UI or data.

## Deploy

- Branch `master`. Pushing to `master` deploys to production on Vercel (project `dedeler/water-brands-website`).
- DNS is on Cloudflare. Product images live on Cloudflare R2 (`img.waterqualityrank.org`), not Vercel image
  optimization; run `npm run images:sync` before deploying new data (see README "Images").
- After a deploy that adds or changes pages: `npm run indexnow` (Bing, Yandex, DuckDuckGo). Google reads
  `/sitemap.xml` through Search Console (URL-prefix property, verified by the meta tag in `src/app/layout.tsx`).
- `src/proxy.ts` rate-limits and blocks script user agents (curl, node fetch, headless Chrome) on catalog pages, so a
  plain `curl` gets 403. Pass a browser `User-Agent` when checking production. Search and AI crawlers are allowlisted
  there; if you add a crawler, add it to `SEARCH_CRAWLER_UA_PATTERNS`, never weaken the scraper list to make a test pass.

## Structured data (JSON-LD)

Search Console emails errors weeks after a bad deploy. In Oct 2026 it flagged 109 Product and Review snippets because
pages used `aggregateRating` without `ratingCount`/`reviewCount`. Rules:

- Our scores are editorial ratings, not user ratings. Mark them up as a `review` (`Review` with `reviewRating` and an
  `Organization` author: `SITE_NAME`), like `src/app/water/[id]/page.tsx`. Never use `aggregateRating` unless there
  are real counted user ratings, and never invent a `ratingCount`.
- A `Product` needs `name` plus at least one of `review`, `aggregateRating` or `offers`.
- Shared builders are in `src/components/seo.tsx`; page-specific blocks sit in each route's `page.tsx`. Keep every
  template consistent: when you fix one product type (water, filter), check the others.
- Check before you push: `npm run build && npm start`, then `npm run check:schema` (samples every page template from
  the local sitemap). It must exit 0. `npm run check:schema:prod` runs the same check on production after deploying.
  For a new schema type, add a rule to `scripts/check-structured-data.mjs` (shared with `free-north-korea`; keep the
  two copies in sync) and test one page in https://search.google.com/test/rich-results.

## Rules

- Data comes from `src/data/*.json`, generated by `npm run build:data`. Don't hand-edit generated JSON; fix the
  builder in `scripts/build-site-data.mjs`.
- New search targets: add entries in `src/lib/rankings.ts` (`/best`), `src/lib/compare.ts` (`/compare`) or
  `src/lib/guides.tsx` (`/guides`). Bump `CONTENT_UPDATED` in `src/lib/site.ts` when content changes.
- UI: follow README "Design & tone". Emojis on purpose, sky-blue active states, opacity-only entrance animations
  (no slide-ups), respect `prefers-reduced-motion`.
- Secrets never enter the repo (it is public). Keys live in Vercel env vars or `.env.local`.
- Before you finish: `npm run lint`, `npm run build` and `npm run check:schema` must pass. Then commit and push to
  `master`.
